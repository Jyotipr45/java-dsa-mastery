# Algorithm Patterns

Patterns are the reusable ideas behind most algorithm problems. Learning to recognize them is the main goal of this repository: if you can spot which pattern a new problem needs, you can solve problems you have never seen before.

Each pattern guide explains what the pattern is, which clues suggest it, why it works, how to apply it step by step, when it fails, and which alternatives to consider. It ends with links to practice problems in this repository.

The clues below are starting points, not rules. Several patterns can fit the same clue, so always check that a pattern's assumptions actually hold before using it.

| Pattern | Common clues | Status |
|---|---|---|
| Two Pointers | Sorted input, or comparing elements from both ends | Planned |
| Sliding Window | Contiguous subarrays or substrings with a condition | Planned |
| Fast and Slow Pointers | Cycles, or finding the middle of a linked list | Planned |
| Prefix Sum | Sums over many ranges of a fixed array | Planned |
| Hashing | Repeated lookups, counting or finding complements | Planned |
| Binary Search | Sorted data, or a monotonic answer space | Planned |
| Monotonic Stack | Next greater or next smaller element | Planned |
| Monotonic Queue | Maximum or minimum of every sliding window | Planned |
| Breadth-First Search | Shortest path in an unweighted graph, level-by-level processing | Planned |
| Depth-First Search | Exploring every path, connected components, tree traversal | Planned |
| Backtracking | Generating all combinations, permutations or valid arrangements | Planned |
| Greedy | A local best choice that provably leads to the global best | Planned |
| Dynamic Programming | Overlapping subproblems and optimal substructure | Planned |
| Topological Sort | Ordering tasks that depend on each other | Planned |
| Union-Find | Grouping elements and checking connectivity as edges are added | Planned |
| Heap and Priority Queue | The k smallest or largest elements, or merging sorted lists | Planned |
| Merge Intervals | Overlapping ranges | Planned |
| Divide and Conquer | Splitting a problem into independent halves and combining the results | Planned |
| Bit Manipulation | Parity, subsets as bitmasks, or values that appear an odd number of times | Planned |
